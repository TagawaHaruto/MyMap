# スポット拡大（約10万件）・関連スポット・工場見学 設計メモ（2026-10-09）

## ユーザーの決定
- 公開方法: Actions でアプリとデータを組み立てて公開し、データを main の履歴に残さない。
- 追加する種類: 飲食店（レストラン・カフェ・スイーツ・パン・ファストフード）、史跡・文化財・宿、お土産・直売所・市場・遊び（スポーツ・釣り・キャンプ等）。寺社・公園の全件は今回は入れない（見込み合計 約10万件。20万件には寺社・公園などの追加が必要）。
- チェーン店: 収集はするが既定で隠し、「チェーン店も表示」で出す（OSM の brand / brand:wikidata タグで判定）。
- 工場見学: ジャンル「🏭工場見学」と「当日参加OK」の絞り込み（厳選データ。walkin / booking 項目）。
- 「詳しく」に 似たスポット（同ジャンル・近い順 5 件）・周辺のスポット（2km 以内 5 件）・近くのカフェ・食事（1km 以内 5 件）。

## 公開の仕組み
- `main`: アプリのコードと手作業のデータ（spots / touring / scenic_roads / prefectures / config）だけ。自動生成のデータは置かない（.gitignore）。
- `gh-pages`: Actions が毎回「main のアプリ＋最新のデータ」を組み立て、**履歴 1 件だけの orphan コミットで強制上書き**する。Pages の Source は `gh-pages` / `/ (root)`。
- collect.yml: workflow_dispatch（アプリの更新依頼）と push（main への変更）で動く。
  - push のとき: 収集はせず、gh-pages の既存データにアプリだけ差し替えて公開。
  - dispatch のとき: 前回のデータ（gh-pages）を読み込んでから収集し、失敗した種類は前回分を残す。
- タイムアウト 60 分（公開リポジトリの Actions は無料）。

## データの分け方
- 25km 四方程度の升目（緯度・経度 0.25 度）×グループで分ける: `data/cells/<group>/<cell>.json`。
  - グループ: `food`（飲食）、`heritage`（史跡・文化財・宿）、`local`（お土産・直売所・市場・遊び）。
  - 既存の `osm_spots.json`（観光スポット 約1.3万件）はそのまま 1 ファイル。
- `data/cells/index.json`: `{ "<group>": { "<cell>": 件数 } }`。
- 項目の形は osm_spots と同じ（id, name, kana?, lat, lon, pref, genres, indoor, url, wp?, note, k）＋ `chain: true`（チェーン店）。
- 大きい種類（レストランなど）は、Overpass の時間切れを避けるため範囲を 2×2 に分けて問い合わせる。

## 画面
- ジャンルに「🍴グルメ」「🏯史跡・宿」「🛍お土産・直売」「⚽遊び・アウトドア」「🏭工場見学」を追加。
- グループのデータは、そのジャンルを選んだときだけ、絞り込みの範囲（移動時間から求めた半径。制限なしは 60km まで）にかかる升目を読み込む。読み込んだ升目は端末に保存（Service Worker）。
- 「全種類」の一覧には飲食などは混ぜない（今までどおり観光スポット中心）。
- チェーン店は既定で隠す（一覧の上に「チェーン店も表示」）。
- 「当日参加OK」チップ（工場見学を選んだときに表示）。
- 「詳しく」: 似たスポット・周辺のスポット・近くのカフェ・食事（その場所の升目だけ読み込む）。
- 名前検索は今のデータ（厳選＋観光スポット＋立ち寄り）。飲食などの全件検索は今回は入れない（名前の一覧だけで数 MB になるため）。

## テスト
- lib: 升目 id の計算、半径にかかる升目、チェーン判定、関連スポットの選び方。
- collector: グループ別のパースと升目への振り分け、2×2 分割、前回分の引き継ぎ、index の作成。
- 画面: ジャンル選択時の升目の読み込み、チェーン店の表示切替、当日参加OK、詳しくの関連スポット。
