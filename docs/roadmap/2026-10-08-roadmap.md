# MyMap 開発ロードマップ（2026-10-08）

6つの視点（屋外での見やすさ、使いやすさ、他のアプリとの比較、ツーリング、データの質、信頼性）から点検し、2人の審査員が「使う人にとっての価値」と「作りやすさ」で採点しました。この2つをまとめたものです。

## 要点（30秒で読めます）

- 大きな問題は2つあります。
  - 開いた直後の画面に、一覧もタブも入りません。画面の上半分を絞り込みとおすすめが占めているためです。
  - 日なたでいちばん見たい「移動時間」と「km」が、いちばん小さく薄い灰色の文字で表示されています。
- **第1弾**は小さな改修11件です。中心は屋外モード、画面の整理、ツーリング地図の不具合の修正です。
- **第2弾**では、ルート沿いの天気、給油所、「今週末」ホームを作ります。**第3弾**では、帰宅時刻の見積もりや、知名度の高い順に並べる機能に取り組みます。
- 約束はすべて守ります。運用費は0円、使っている最中にAIは使わない、定期実行は増やさない、の3つです。

## 1. 直射日光の下でも見やすくする工夫

### 前提：走っている間は見ない・触らない

走行中にスマホを手に持つことや、画面を見続けることは、道路交通法（第71条第5号の5）で禁止されています。そこでMyMapは「停車中に数秒で判断できる画面」を目指します。ちらっと見て読むのは「何km先」「何時」など1〜2項目に絞ります。走っている間の道案内は、Googleマップの音声ナビに任せます。

### なぜ日なたで見えにくくなるのか

画面に当たった日光が反射して、黒い文字の上にも明るさが足されます。すると黒が灰色に浮き、文字と背景の明るさの差が大きく縮みます。この差を「コントラスト比」と呼びます。読みやすさの目安は文字で4.5以上、ボタンの枠などで3以上です。今のMyMapの色で計算すると、次のとおりです。

| 見る場所 | 本文（ほぼ黒） | 補助の文字（灰色） | 枠線（薄い灰色） |
|---|---|---|---|
| 室内 | 17.4 | 8.5 | 3.0 |
| 日陰・曇り | 4.8 | **3.9** | **2.3** |
| 直射日光 | **1.9** | **1.8** | **1.5** |

（反射する光の量は、日陰では画面の白の約2割、直射日光では画面の白とほぼ同じ、と置いた概算です。太字は目安を下回る値です。）

この表から分かることは2つです。

1. **色をこれ以上濃くしても、ほとんど変わりません。** 本文を真っ黒にしても、日陰で4.8が5.0に、直射日光で1.9が2.0になるだけです。
2. **効くのは、文字を大きく太くすること、ボタンを塗りつぶすこと、読む量を減らすこと、そして反射そのものを減らすことです。** 明るさの差が小さくても、文字が大きく太ければ形で読み取れます。

### MyMapでやること

| 工夫 | MyMapで具体的にやること | なぜ効くのか |
|---|---|---|
| 灰色の文字をやめる | 移動時間・料金・km・件数を、薄い灰色から黒の太字にする | 灰色の文字は日陰で3.9まで下がる。黒に近い色なら4.8で目安を超える |
| 文字を大きくする | 屋外モードでは全体を1.25倍にする（14px→17.5px、16px→20px）。ツーリングのkm表示は約2倍の特大数字にする | ホルダーに付けたスマホ（目から約60cm）で読める大きさの目安は、車載表示の規格（ISO 15008）で「約20分角」の見え方。今の14pxは約14分角で足りない |
| 枠線を太く濃くする | チップ・カード・入力欄の枠を、1pxの薄い灰色から2pxの黒に近い色に変える | 薄い灰色の線は直射日光で1.5まで下がり、ボタンの形が見えなくなる |
| 色の違いに頼らない | ⭐・行った・雨モードは、押すと青く塗りつぶして✓を付ける。押せないボタンは枠を破線にする | 今は淡い水色の背景の差（約1.1）だけで区別していて、屋外ではまず見分けられない |
| 押す場所を広くする | 屋外モードではボタンの高さを44pxから64px（約11mm）に、ボタンの間隔を6pxから12pxにする | 指先の幅は10〜14mmあり、グローブをはめるとさらに太くなる。隣どうしの #X と #Instagram を押し間違えにくくなる |
| 昼は白地に黒字にする | 屋外モードの間は、端末をダークモードにしていても白い背景で表示する | 白地に黒字のほうが速く正確に読めるという研究がある（Piepenbrockら 2013・2014）。黒い背景だと空やヘルメットの映り込みが目立つ |
| 地図の線と印を目立たせる | ルートは白い縁取りの付いた太い線にする。立ち寄り候補は白抜きの丸、選んだ候補は塗りつぶしの丸に番号を付ける | 今の灰色と青の丸は、明るさの差がほぼない（1.09）。明るさの差を付ければ、色の多い地図の上でも浮き上がって見える |
| 押したことが伝わるようにする | 押した瞬間に短く振動させる（Androidのみ）。押している間は太い黒枠を出す。ルートを検索している間は「検索中…」と出す | 日なたでは画面の変化が見えにくく、グローブでは押した感触もないので、二度押しが起きやすい |
| 画面を消さない | ツーリングタブを開いている間だけ、画面が自動で消えないようにする | ヘルメットをかぶっていると顔認証が通らず、画面が消えるたびにパスコードを打つことになる |

**切り替え方**：画面上部に「☀屋外」ボタンを置き、1回押すと切り替わります。選んだ状態は次に開いたときも残ります。iPhoneの「コントラストを上げる」（設定→アクセシビリティ）をオンにしている場合は、最初から屋外モードで開きます。周囲の明るさで自動的に切り替える機能はiPhoneでは使えないので、手動での切り替えが基本になります（最後の「決めてほしいこと①」）。

### アプリの外でもできること（今日から試せます）

- **明るさの自動調整をオンにする**：機種によっては、自動調整がオンのときだけ、日なた用の最大の明るさまで上がります。
- **反射を減らす**：反射防止（ノングレア）フィルムを貼ります。ホルダーは太陽や空が画面に映り込まない角度に向けます。上の表の数字を根本から良くできるのは、この方法だけです。
- **本体を熱くしない**：スマホは熱くなると、自動で画面を暗くします。直射日光が当たり続けないようにしてください。
- **偏光サングラスをかけるとき**：画面の向きによっては暗く見えます。ホルダーで縦向きと横向きを試してください。

## 2. 優先順位の付け方

2人の審査の点数（それぞれ5点満点）を掛け合わせて順位を付け、似た案は1つにまとめました。同じくらいの点数なら、日差し対策とツーリング当日の困りごとを先にしています。
規模の目安は次のとおりです。**S**＝小（数十行程度）、**M**＝中（画面や処理を1つ足す）、**L**＝大（複数の画面とデータにまたがる）。

## 6. 見送り（約束に反する、または実現が難しい案）

- **明るさセンサーによる全自動の切り替え**：iPhoneでは使えず、AndroidのChromeでも試験中の機能にとどまっています。
- **走行中の自動読み上げや自動表示**：ナビ中はGoogleマップが前面にあり、MyMapは裏側では動けません。安全の面からも作りません。
- **地図画像を保存してオフラインで使う**：OpenStreetMapの利用規約で、まとめて保存することが禁止されています。代わりにGPXを書き出し、オフラインで使える地図アプリで見ます（第2弾）。
- **雨雲を地図に重ねる（RainViewer）**：無料で使える範囲では表示が粗く、個人利用に限られるので、テンプレートとして配る用途に向きません。気象庁へのリンクで代わりにします。
- **通行規制の自動取得**：無料で機械が読める形の規制情報がありません。Webページから文字を抜き取る方法（スクレイピング）は、規約と保守の面から使えません。手で書いた注意書き、公式ページへのリンク、ハッシュタグ検索のリンクで代わりにします。
- **くねくねした道を優先するルート検索と、曲がり具合の数値化**：無料の公開ルート検索ではできません。曲がり具合の数値も、経路データが粗いため当てになりません。
- **国土地理院の住所検索で全スポットに都県を付ける**：約1.1万回の問い合わせに3時間以上かかります。収集ジョブの30分の上限を超え、相手のサーバーにも負担をかけます。
- **公式サイトから料金や営業時間を自動で読み取り、候補から外す**：サイトごとに書き方が違うので壊れやすく、行ける場所を誤って外すおそれもあります。書いてあるとおりに表示するだけにします。
- **夜に地図の色を反転させる**：地図が読みにくくなります。明るさを落とすだけにします。
- **DADSの色の値を手で書き写す**：DADSが更新されても反映されなくなります。公式の定義ファイルをそのまま手元に置きます。
- **独自ドメイン、専用のGitHub組織、厳しいセキュリティ設定（CSP）**：費用がかかる、家族の手間が増える、機能を足すたびに壊れやすい、のいずれかに当たります。トークンが有効かの確認と「GitHubで更新」リンクだけを取り入れます。
- **収集に失敗したら全種類を毎日取り直す**：公開サーバーの負担が増えます。失敗した種類だけを取り直します。
