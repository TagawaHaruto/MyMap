## 共通の取得方法

- データセット探索: 東京都オープンデータカタログ CKAN API
  `GET https://catalog.data.metro.tokyo.lg.jp/api/3/action/package_search?rows=1000&q=<語>`（二輪, 自動二輪, オートバイ, バイク, 原付, 原動機付自転車, 駐輪場, 自転車駐車場, 自転車等駐車場, 駐車場, 駐輪, 自転車置場 など）
  メタデータ: `GET https://catalog.data.metro.tokyo.lg.jp/api/3/action/package_show?id=<datasetId>`
- API カタログのデータ取得（spec ページは Swagger 2.0。GET ではなく **POST**）:
  ```
  POST https://service.api.metro.tokyo.lg.jp/api/<apiId>/json?limit=1000&offset=0
  Content-Type: application/json
  body: {}
  ```
  レスポンス `{total, hits:[...], metadata:{updated,...}}`。total>1000 の場合は offset でページングする。
  **apiId = `<datasetId>-<md5(リソースURL文字列)>-0`**（例: md5("https://www.city.chuo.lg.jp/documents/984/kuei_nirinsha.csv") = a9033dfe…）。リソースURLが変わると apiId も変わるので、週次で再取得するときは package_show でリソースURLを取り直して apiId を再計算するのが確実です。
- API に載っていないもの（404）は、リソースURLの CSV / XLSX / ZIP を直接ダウンロード（UTF-8 か Shift_JIS）。
- ネットワーク: `node --use-system-ca` の fetch を使用（Python の HTTPS は SSL インスペクションで失敗する）。
- ジオコーディング: 座標がない行は GSI `https://msearch.gsi.go.jp/address-search/AddressSearch?q=<住所>` を使用（12件）。住所がない行は GSI 逆ジオコーダ `https://mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress?lat=&lon=` で「東京都<区市>町丁目付近」を補完（51件。addr が「…付近」で終わるもの）。座標は小数5桁に丸め。
- 同名かつ約50m以内の重複は除去。fee は200文字で切り詰め。
- 判定ルール: moto = 自動二輪（50cc超）可、moped = 原付（50cc以下）可。「バイク」とだけ書かれ排気量区分がない場合は moto=true, moped=true（推定）。「125ccまで」「〜125」は 51〜125cc を含むので moto=true とする。
- ライセンス: 使用した全データセットのカタログ license_id は CC-BY-4.0（出力では "CC BY 4.0"）。
- 処理スクリプト（再実行用、セッション一時領域）: `…\scratchpad\moto\fetchall.js`（取得）, `build.js`（解析）, `finalize.js`（ジオコーディング・出力）

## 再実行の手順

作業フォルダ `<W>`（取得したファイルを置く。スクリプトとは別のフォルダにする）を決めて、このフォルダで順に実行する。

```
node --use-system-ca jp_search.js   <W>   # カタログ（CKAN / dataeye の CKAN 互換 API）を語で検索 → <W>/pkgs.json
node --use-system-ca jp_fetch.js    <W>   # 題名で絞った候補＋カタログ外の配布ファイル（EXTRA）を取得し表にする → <W>/raw, <W>/tab, <W>/index.json
node jp_build.js                    <W>   # データセットごとの判定 → <W>/stage_jp.json
node --use-system-ca jp_finalize.js <W> [出力先]   # ジオコーディング・重複除去・東京分と結合 → 出力, <W>/report_jp.json
```

- XLSX は `jp_xlsx.py`（openpyxl）で読む。古い .xls（岐阜市・熊谷市・益田市など）は xlrd が要る（`pip install xlrd`、または xlrd の wheel を `PYTHONPATH` に置く）。中身が xlsx の .xls は先頭のバイトで判定して openpyxl で読む。
- 検索するカタログ: BODIK ODCS、G空間情報センター、札幌市・石川県・岐阜県・相模原市・山口県・姫路市・宇都宮市の CKAN、千葉県・埼玉県・岡山県・宮城県・広島（hiroshima-opendata）・島根・岩手の dataeye（`/ckan_api/package_search`。dataeye のライセンスはリソースごとの `resource_license_id`）。語: 自動二輪, 二輪, バイク, オートバイ, 原付, 原動機付自転車, 駐輪場, 駐輪, 自転車駐車場, 自転車等駐車場, 公営駐車場, 公営駐輪場。
- カタログ外（市のサイト・地図システム wagmap 等）の配布ファイルは `jp_fetch.js` の `EXTRA` に URL とライセンスを書く。wagmap の `OpenDataDetail?lid=X&mids=Y` は `…/opendatafile/map_Y/CSV/opendata_X.csv` に置き換えて取得する。
- 大阪市（mapnavi）のように node の TLS が古い鍵で失敗するホストは curl で取り直す（TLS の検証は無効にしない）。
- e-Gov データポータルの CKAN API は国の資料が中心で、自治体の駐輪場データは出てこなかったので検索先から外した。
- 判定はデータセットごとに `jp_build.js` に書いている（列の名前・書き方がばらばらなため）。新しいデータセットを足すときは `run('<id>', …)` を 1 つ足す。自治体標準オープンデータセットの「公営駐車場一覧」（車種・最大駐車台数_バイク）は `stdCarPark()` で共通に読める。

## 判定ルール（全国版。東京版の規則を引き継ぐ）

- moto = 自動二輪（50cc超）可、moped = 原付（50cc以下）可。どちらも書かれていない行は採らない。推測で台数や可否を作らない。
- 「バイク」「二輪車」とだけあり排気量の区分がない → moto/moped とも true + `ccUnknown: true`（東京版と同じ）。
- 自動二輪が「125cc以下」「原付二種」「小型」に限られる → moto true + `ccUnknown: true`（大型は止められない。アプリでは「排気量の制限は現地で確認」と出る）。
- 「自動二輪」「普通自動二輪」「大型」「125cc超」などが明記 → moto true（ccUnknown なし）。原付が書かれていなければ moped は false（例: 浜松の自動二輪車駐車場、姫路の大手前公園地下=125cc以下・原付不可）。
- 越谷市の「バイク小・中・大」、姫路市の「バイク(小)(中)(大)」は区分の定義が書かれていないので、「大」があるときだけ ccUnknown なし、それ以外は ccUnknown。
- capacity は二輪・原付の台数が分かるときだけ（自転車と合算の総数しかないときは null）。
- 民営の施設も、自治体の公式データに載っていれば含める（大阪市の mapnavi、姫路市の「民営」など）。
- 座標がない行は GSI 住所検索の 1件目（結果の住所に市区町村名が入っていないものは使わない）。住所がない行は GSI 逆ジオコーダ＋`data/muni.json` で「…付近」を補う。座標の小数が 2桁以下（約1km ずれる）のときは住所から取り直す（長岡京市）。同名で約 50m 以内は 1件に（大阪市は時間貸を月極より優先）。
